# ArbitrageIQ

A local decision-support tool for an Indian ecommerce reseller: import product and
transaction CSVs, compute **contribution profit** per SKU under configurable fee, GST and
refund assumptions, and compare two heuristics for spending an inventory budget.

Every command in this file was executed on this machine, and the results quoted are the
ones actually observed. Where a command did not work, that is said plainly.

## What this is, and what it is not

It is a local tool. It reads CSV files that you supply, computes money in `Decimal`
(never in a float), and renders what its own API returns. It ships with synthetic demo
data so it can be evaluated without any real seller data.

It is **not** a scraper, a sales forecaster, a tax adviser, an accounting system, or an
automation tool. It makes no outbound network call at runtime, holds no credentials, and
never claims its two budget heuristics are an optimisation. Contribution profit excludes
overheads and income tax, so it is not money in a bank account.

### Data policy

- **Synthetic or owner-authorised data only.** `data/sample/*.csv` is generated by
  `scripts/make_sample_data.py` and contains no real brand, person, phone number, address
  or order ID.
- Your own imports belong in `data/private/`, which is gitignored, as are `*.db`,
  `*.sqlite*` and `.env`.
- There is no authentication and no multi-user support. Bind the API to localhost only.

## Requirements

- Python 3.12 or newer (3.14.2 was used here).
- Node.js 20 or newer and npm (Node v24.14.1 / npm 11.14.1 were used here).

## Setup

### 1. Backend environment

```powershell
cd E:\ArbitrageIQ
python -m venv .venv                 # or: py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
```

**Observed on this machine.** Both `py -3.12 -m venv .venv` and the Windows Store
`python.exe` on `PATH` refuse to run in this shell — `Program 'py.exe' failed to run: The
file cannot be accessed by the system`, and the same for `python.exe`. The environment was
therefore created with an existing interpreter by absolute path, which is the command that
was actually observed to work:

```powershell
& "E:\ArbitrageIQ\.venv\Scripts\python.exe" -m venv .venv
```

`pip install -r backend\requirements.txt` then succeeded against the **pinned** manifest
(exit 0), installing FastAPI, uvicorn, SQLAlchemy, pandas, pytest, httpx and ruff among
others.

### 2. Initialise and seed the local database

A fresh checkout has **no database file**, and the data endpoints return `500` until this
step is run. The path is derived from the source tree (`data/private/arbitrageiq.db`), and
the directory is created if missing.

```powershell
cd backend
& ..\.venv\Scripts\python.exe -m arbitrageiq.db init
& ..\.venv\Scripts\python.exe -m arbitrageiq.db seed
```

Observed output:

```
{"created": true, "path": "…\data\private\arbitrageiq.db"}
{"seeded": true, "products": 10, "transactions": 40, "fee_assumptions": 1}
```

Re-running `seed` is safe; the database file is disposable and can be deleted and reseeded
at any time.

## Running it

### The API

The documented command is:

```powershell
cd E:\ArbitrageIQ\backend
uvicorn arbitrageiq.api:app --host 127.0.0.1 --port 8000
```

**This does not work on this machine, and the limitation is stated rather than hidden.**
Python 3.14.2 on Windows drives uvicorn's Proactor event loop, whose `accept()` fails:

```
OSError: [WinError 10014] The system detected an invalid pointer address in attempting to
use a pointer argument in a call
    File "…\asyncio\windows_events.py", line 567, in accept_coro
```

The socket binds, but every connection times out (`The operation has timed out`). What does
work here is leaving the event loop alone (`loop="none"`) and driving the server from an
explicit selector loop:

```powershell
cd E:\ArbitrageIQ\backend
& ..\.venv\Scripts\python.exe -c "import asyncio, uvicorn; c = uvicorn.Config('arbitrageiq.api:app', host='127.0.0.1', port=8000, loop='none'); s = uvicorn.Server(c); asyncio.Runner(loop_factory=asyncio.SelectorEventLoop).run(s.serve())"
```

Observed against a fresh environment in a copied tree:
`GET /api/v1/health` → `200 {"status":"ok","version":"0.0.0","db":"reachable"}`, and
`GET /api/v1/products` → `200` with the ten seeded SKUs after the seed step below. The
check was made on port `8001` because `8000` was occupied by another copy already running;
the only difference from the command above is the port number.

Interactive OpenAPI documentation is at `http://127.0.0.1:8000/docs`.

### The frontend

```powershell
cd E:\ArbitrageIQ\frontend
npm run dev
```

Vite serves `http://localhost:5173` and proxies `/api` to `http://127.0.0.1:8000`
(`frontend/vite.config.ts`), so both processes must be running.

Routes: `/` is the public landing page; the five views are `/app/overview`,
`/app/import`, `/app/profitability`, `/app/budget-lab` and `/app/methodology`.

The one failure is `tests/test_api.py::test_at_8_2_get_assumptions_returns_the_full_object_with_string_money`,
which asserts `tcs_rate == "0.005"`. Every assumption column is declared `Numeric(18, 2)`,
so SQLite stores `0.005` as `0.01` and `0.001` as `0.00`. It is a known, recorded defect
(`plans/PROGRESS.md` §8 DEV-17) with a one-line fix in a file owned by a completed task,
so it is left in place rather than silently corrected. **The suite is not green**: 245 of
246 tests pass.

## Known limitations

1. **`uvicorn` on the command line cannot accept connections here** — see *The API* above.
   Use the selector-loop form.
2. **One test fails**, on the rate-precision defect described above.
3. **No git repository exists in this working tree**, so history-based checks (for example
   `git log -p -S "password"`) could not be run. A secret sweep over the working tree is
   clean; the history half of the check is unverified.
4. **No CORS middleware is configured at all.** That is stricter than an allowlist — there
   is no cross-origin access to misconfigure, `*` included — but it also means a browser on
   a different origin than the Vite dev server cannot call the API directly.
5. **`favicon.ico` is absent**, so the browser logs one `404` for it.

## Deferred integrations

None of the following exists. None has been designed, registered or prototyped, and no
placeholder endpoint, mock credential or "coming soon" panel for one appears anywhere in
this repository.

| Integration | State |
|---|---|

| Local REST API consumed by the SPA | **Built** — nine paths (ten operations) under `/api/v1`, per `/openapi.json` |
| FastAPI `/docs` OpenAPI UI | **Built** |
| Batch delete of an import (`DELETE /import/{batch_id}`) | Deferred (P1) |
| Public deployment of the demo | Deferred (P1, optional). Demo data only |
| Amazon Selling Partner API (SP-API) | Deferred (P2). Not registered, no credentials |
| Amazon Seller Central report import | Deferred (P2). Report schemas are versioned and change without notice |
| Wholesale price scraping / supplier discovery | **Prohibited.** Not a backlog item |
| Google Trends ingestion | Deferred (P2). Search interest is not sales |
| Authentication / SSO | Deferred (P2). No identity layer, no user table, no session |

## Not tax advice

Marketplace fee rates, GST rates and thresholds in this tool are illustrative demo
assumptions with a recorded effective date. They are not current Amazon or Indian tax
figures, and the tool does not determine GST registration obligations or ITC eligibility.
Verify with a qualified professional before using any figure for a business decision.
